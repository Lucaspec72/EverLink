EVERLINK HOST - BUILD INSTRUCTIONS
=================================================

REQUIREMENTS
------------
- Windows 10/11
- .NET 8 SDK
  Check if installed:      dotnet --version
  Install if missing:      winget install Microsoft.DotNet.SDK.8
  (Close and reopen PowerShell after installing so PATH updates)

BUILDING
--------
1. Open PowerShell and navigate to the Host folder:
     cd path\to\EverLink\Host

2. Build:
     dotnet build

   First build will restore NuGet packages (System.IO.Ports, System.Management,
   ppy.SDL3-CS) - needs internet access. Subsequent builds are faster.

3. CHECK FOR SDL3.dll: after building, look in the output folder
   (bin\Debug\net8.0-windows\win-x64\ or similar) for SDL3.dll. The SDL3-CS
   package SHOULD copy this automatically as part of the build. If it's
   there, skip to step 4.

   If SDL3.dll is NOT there: download it manually.
     - Go to https://github.com/libsdl-org/SDL/releases
     - Download the Windows x64 binary release (look for a filename like
       SDL3-3.x.x-win32-x64.zip, NOT the "devel" or source versions)
     - Extract SDL3.dll and place it in the same folder as
       EverLinkHost.exe (the build output folder from step 3)
   The app will show a clear startup error message if SDL3.dll is missing,
   telling you the same thing.

4. Run:
     dotnet run

   A window should open. Since this is a WinExe (GUI) app, PowerShell will
   just sit idle while it's running and return when you close the window.

CONTROLLER READING: SDL3, NOT XINPUT
----------------------------------------
The app reads controllers via SDL3 rather than XInput. This was a
deliberate choice - XInput deliberately withholds the Guide/Xbox button
from applications, and only supports Xbox-style controllers. SDL3 exposes
the Guide button as a normal readable button and supports a much wider
range of controllers (PlayStation, Switch Pro, generic pads) via SDL's
community-maintained controller database.

DEVICE DETECTION (EverLink Relays only)
---------------------------------------------------
The EverLink Relays panel does NOT show every COM port on your system - only
ones that respond correctly to an identification ping, meaning boards
actually running EverLink Relay firmware. Unrelated serial devices
(mice, modems, etc.) simply won't show up at all.

Rescanning briefly opens and probes each candidate COM port in turn, so it
can take a moment with several devices connected - this is normal. Ports
already in use by a connected Relay are skipped (not re-probed) since
they're already confirmed and can't be opened twice at once.

Right-click a found device for:
  - Rename... - give it a friendly nickname (e.g. "Player 1"). Nicknames are
    tied to the device's own hardware MAC address (read from the chip itself
    during the identification ping).

A warning triangle (/!\) next to a device means that specific board's chip
model has no native USB peripheral (plain ESP32/C3 boards, as opposed to
S2/S3/P4).

BUTTON REMAPPING
-----------------
The panel on the right of the live preview lets you change which physical
input drives each output sent to the Relay. Defaults to identity mapping
(A->A, B->B, etc).

See ../EverLink_Protocol.md for the exact serial packet format Host sends -
that's the contract Relay firmware needs to match.
